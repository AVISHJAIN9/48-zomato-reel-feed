# 14.7 System Design: Messaging, Queues & Async Video Processing

---

## 1. What It Is in Plain Words
Asynchronous messaging and task queuing offload heavy, slow, or failure-prone tasks (like video transcoding, thumbnail extraction, and AI moderation) away from the synchronous user-facing HTTP request-response cycle, executing them in background worker pools.

---

## 2. Whether and How THIS Project Uses It
* **Current Status:** In the active codebase, file upload to ImageKit is handled **synchronously** within `foodController.createFood` (`await storageService.uploadFile(...)`).
* **Why This Was Acceptable for MVP:** With only a few test partners, synchronous uploads allowed immediate feedback and kept the codebase dependency footprint minimal.
* **Production Architecture:** High-throughput video uploads must be processed **asynchronously** via a Redis-backed queue like **BullMQ**.

## 3. Queue Technologies Compared

| Queue / Stream System | Architecture | Latency | Throughput | Persistence | Dead Letter Queues | Complexity | Fit With MERN Stack |
|---|---|---|---|---|---|---|---|
| **BullMQ (Redis) (Recommended)** | Redis-backed Job Queue | **Ultra-Low (<1ms)** | Very High (~50k msgs/sec) | Redis RDB/AOF | **Native** | **Low (Node native)** | **10/10** |
| **RabbitMQ** | AMQP Message Broker | Low (~2ms) | High (~30k msgs/sec) | Disk & RAM | Native | Moderate | 8/10 |
| **Apache Kafka** | Distributed Commit Log | Low (~5ms) | **Extreme (>1M msgs/sec)** | Append-only log on disk | Requires custom offset logic | Very Steep | 5/10 (Overkill for upload jobs) |
| **AWS SQS** | Managed Cloud Queue | Moderate (~20ms) | Unlimited | Managed (AWS) | Native | Low (AWS bound) | 7/10 |

## 4. Message Delivery Semantics & Idempotency
* **At-Most-Once:** Message sent once; never retried. Risk of dropped video processing jobs.
* **At-Least-Once (Standard):** Message guaranteed to be delivered; may be delivered multiple times during network retries.
* **Idempotent Consumers:** Because BullMQ operates with at-least-once delivery, video workers must be idempotent:
  ```javascript
  // Idempotent worker check
  const food = await foodModel.findById(job.data.foodId);
  if (food.status === "ACTIVE") {
      logger.info("Job already completed. Skipping.");
      return;
  }
  ```
* **Dead Letter Queue (DLQ):** If a corrupt video crashes FFmpeg, the job fails 3 times and is moved to a Dead Letter Queue (`failed:video-transcode`) for manual developer inspection rather than crashing the worker fleet.

---

## 5. What Breaks at 10x, 100x, 1000x Load
* **10x:** Synchronous uploads trigger client HTTP 504 Gateway Timeouts when slow mobile connections stall; resolved by moving to BullMQ.
* **100x:** Background transcoding workers saturate server CPU; resolved by autoscaling worker containers independently from API containers.
* **1000x:** Queue backlog grows faster than workers can process; resolved by implementing AWS MediaConvert serverless transcoding fleets.
